# 00. Архитектура и pipeline

## Граф (langgraph)

```
START
  → [Входные фильтры] (Python)            → fail → END(REJECT_INPUT)
  → [creator] (LLM)
  → [Формат-контроль] (Python)            → fail → retry c review
  → [Постфильтр ответа] (Python)          → fail → retry c review
  → [validator] (Python + LLM)            → fail → retry c review
      PASS → [Постобработка] (Python): дисклеймер + финальная проверка
             → fail → retry c review
             → ok  → END(ACCEPT)
  → попытки исчерпаны → END(REJECT_VALIDATION)
```

## Повторные попытки (retry)
- Лимит: **3 попытки** на карточку (от нас не требуется realtime).
- Каждая попытка после первой (2-я, 3-я) получает:
  исходную карточку + **свою предыдущую попытку** + **review** — список
  упавших пунктов (код + причина; для формат-контроля — «формат не
  распознан, шаблон: ...»).
- Никаких других веток: агенты не рождают агентов, циклов validator↔validator нет.

## Политика сбоев
- Любая ошибка LLM (таймаут, ошибка API, пустой ответ, нераспарсируемый
  ответ валидатора) → **отбрасываем**, логируем.
- Ответ никогда не «чинится» кодом: только retry (с создателем) или отброс.

## Порог (сводка; детали — spec/03)
- Обязательные (5): блокировка повышения уровня, факт-чек по карточке,
  верные правила уровней, дисклеймер (посимвольно, на финальном тексте),
  нет «Дополнительно запрещено».
- Важные (3): уважительный тон, деловой стиль, покрытие ≥ 75% информации.
- **PASS = все 5 обязательных И не менее 2 из 3 важных.**
- Желательные (3): креативность, PUSH не повторяет CARD, полное покрытие —
  только в лог, не блокируют.
