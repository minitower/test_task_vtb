# 02. Контракт ответа creator (обязательное условие фильтрации)

Creator (LLM) обязан выдать ТОЛЬКО такой текст, ничего больше:

```
PUSH: <одна строка, ≤ 70 символов>
CARD: <один абзац, ≤ 350 символов>
```

Требования к содержимому:

- без JSON, без заголовков, без нумерации, без служебных полей карточки;
- без дисклеймера — его добавляет код в постобработке (spec/04);
- без ссылок, QR, кнопок; не более одного «!» за всё сообщение;
- без STOP/SKIP-логики: стоп-условия решаются входными фильтрами (spec/01),
  creator получает только чистые карточки и всегда выдаёт текст.

## Формат-контроль (Python, детерминированный)

- Регулярный разбор ровно двух секций `PUSH:` и `CARD:` в этом порядке.
- Длинны: PUSH ≤ 70, CARD ≤ 350.
- Дисклеймер из `rules.csv` по offer_id НЕ должен присутствовать в тексте
  creator (иначе постобработка даст дубль) → нарушение формата.
- Отсутствуют маркеры инъекций и служебные поля (пересканирование ответа).
- Ответ **не должен содержать** тэг `<user_input>` (тег — внутренняя
  разметка промпта, не контракт ответа) → нарушение формата.

Провал формат-контроля → retry (spec/00) с review
«Формат не распознан. Шаблон: PUSH: … / CARD: … , ограничения …».
Это обязательное условие: нераспознанный ответ не попадает в валидацию.

## Retry-review (что получает creator при 2-й и 3-й попытках)

- исходная карточка (как при первой попытке);
- текст предыдущей попытки;
- review: нумерованный список упавших пунктов — код + короткая причина
  (из формат-контроля, Python-checks и/или verdict валидатора), и строка
  «исправь только эти пункты, остальное не меняй».
