# 04. Постобработка финального ответа (Python, не LLM)

Выполняется ПОСЛЕ PASS валидатора, до вывода. Результат — финальный
текст, который идёт клиенту.

## 1. Дисклеймер
- Дисклеймер берётся из `data/rules.csv` по `offer_id` — строкой, дословно.
- Добавляется кодом в конец текста CARD: `CARD: <текст creator>\n<дисклеймер>`.
- LLM дисклеймером НЕ занимается: он не входит в контракт ответа
  (spec/02) и не передаётся creator как «добавь дисклеймер».
- Двухкратное вхождение дисклеймера (creator сам вставил + код добавил)
  — нарушение формата (spec/02) на этапе формат-контроля;
  если всё же проскочило — постобработка делает idempotent-вставку
  (вставляет только если дословной строки ещё нет) и роняет лог-event.

## 2. Финальный контроль (Python, после вставки дисклеймера)
- D1: дословное (посимвольное) вхождение дисклеймера в финальном тексте.
  (Итоговый D1 валидатора считается именно на этом тексте — spec/03.)
- Повторный скан на маркеры инъекций, служебные поля (client_ref,
  offer_id, flags, JSON-обёртки) и на сам тэг `<user_input>`. Сработал →
  отброс, не правка.
- Финальная длинна: PUSH ≤ 70, CARD ≤ 350 (+ дисклеймер).

## 3. Результат
- PASS финального контроля → вывод (лог: карточка, попытка, вердикты,
  финальный текст) → конец.
- Любой провал → отброс (retry, если попытки остались; иначе REJECT_VALIDATION).
